## Decision and alternatives

Recommend a single transactional Firestore quota namespace owned by a private GCP admission/writer boundary, plus Vercel edge protection as defense in depth. This works independently of the Vercel compute plan. The writer must perform the authoritative admission itself after authentication and before its mutation transaction, covering every invoker and restart. Do not spend two permits by independently admitting the same dispatch in BFF and writer: the reference BFF hook will move behind the private writer boundary, or use a one-use server-side admission protocol accepted under #87. No browser-issued permit is authority.

## Executable contract

`commandQuota.ts` defines the reference algorithm; `commandQuota.fixture.ts` is an offline serializable mock only. There is intentionally no network store adapter or environment switch to select this mock. Default `HttpDiscoveryCommandClient` admission always returns 503 `WRITE_UNAVAILABLE`, even if somebody enables a command flag. It never falls back to its local 20-attempt backstop. Flags off still return 404 before authentication, quota, credentials or upstream access. Reads and PROD are outside this hook.

| Scope                               | Rejection (`discovery.reject`)                 | Promotion (`discovery.promote`, remains disabled) |
| ----------------------------------- | ---------------------------------------------- | ------------------------------------------------- |
| Verified actor / rolling 60 seconds | 20                                             | 5                                                 |
| Operation / rolling 60 seconds      | 40                                             | 10                                                |
| All operations / rolling 60 seconds | 50 total                                       | Shared                                            |
| All operations / UTC day            | 500 total                                      | Shared                                            |
| In flight                           | 1 per actor, 2 globally across both operations | Shared                                            |

These are conservative proposed STAGING values requiring #87 acceptance. Admission uses the exact fresh verified subject and capability. HMAC-SHA256 with an operator-managed secret (at least 32 bytes), stable across instances/restarts, pseudonymizes actor IDs. No JWT, idempotency key, candidate URL, DTO or provider content enters quota state or quota logs. Pseudonyms remain personal data: restrict access and retention. The store receives only version, timestamps, pseudonyms, operation, bounded counters and independently random permit IDs. At most 50 admissions and 2 active entries are retained. No actor map grows indefinitely.

One serializable durable transaction tests and increments every budget and reserves a slot atomically in a fixed STAGING namespace. It must provide trusted store time, bounded retries/deadline, rollback on denial, and no external effects inside a transaction callback (Firestore may rerun callbacks). Store timeout, malformed state, credentials failure or uncertain commit => 503, zero writer dispatch. A committed permit with a lost response remains occupied. No per-instance fallback is permitted. All clients use the same version/policy/namespace/identity secret; policy or secret rotation requires disabling and draining first. Production must use a separate inaccessible namespace and identity.

Denied quota => 429 `RATE_LIMITED`, `Retry-After: 60`, no-store and a safe request ID. Sixty seconds is the rolling-window retry hint; it does not guarantee a daily/concurrency denial has cleared. Do not automatically retry. Store failure => safe 503 with no backend text. The BFF rechecks membership after quota latency and before dispatch, including the exact charged subject. It forwards the original `Idempotency-Key` and payload without generating replacements. Valid DTO attempts and replays consume budget, regardless of business result; malformed DTOs are rejected earlier by the existing bounded local backstop.

A validated definitive response releases only the concurrency slot, never rate/daily counters. Timeout, unknown transport result, malformed receipt and upstream 503 retain the slot. Slots have **no automatic expiry**: process restart, midnight and elapsed time cannot authorize another potentially concurrent writer. A verified 429/409/4xx is treated as completed transport work; #87 must prove the writer returns these only after mutation execution has ended. Failed release leaves the slot occupied without converting a confirmed receipt into a replay. Reconciliation is a separate privileged operator procedure, never a browser endpoint: disable gates, prove the relevant writer execution has stopped/completed, correlate approved audit evidence, then remove only its permit. Keep idempotent review receipts in the Engine. With two abandoned slots all commands stop until reconciliation; this availability tradeoff is intentional. A future automatic expiry requires fencing accepted by the writer, not a TTL assumption.

## Configuration, costs and rollout handoff to #87

Use only `sports-events-web-staging` (`prj_MU4pprIXpAdKUGcBPx8uWztULHxb`), `develop`, and GCP `moumeet-staging`, `europe-west9`. Preserve pinned OIDC issuer/audience/project/branch, separate writer invoker, private authenticated Cloud Run and reader separation in [the BFF runbook](discovery-command-bff.md). Public Vercel ingress cannot establish writer identity; keep IAM authentication on the Run URL. The approved network/ingress mode must actually accept Vercel WIF traffic: do not assume IAM tokens alone make Vercel traffic internal. No public alternate writer route or unthrottled invoker may bypass authoritative admission.

Firestore's pricing page defaults to Iowa: $0.03/100k reads, $0.09/100k writes, $0.01/100k deletes, before free allowances. These are a verified reference quote, **not a Paris quote**; record the europe-west9 SKU, currency, existing DB free-tier eligibility and any egress before approval. A singleton implementation uses roughly 1 read + 1 write for acquire, 1 read + 1 write for release. At 500 admitted/day this is 1000 reads + 1000 writes/day before retries/denials, about $0.036/30 days at those reference rates without allowance. Denials and contention still cost reads; malicious input/authentication, Run compute, Vercel requests, network and logs are not bounded by the admitted-command counter. This is not a total spend guarantee. Budget the full path and add edge throttling before exposure. No third-party account is needed; Redis/Upstash would add separate account/pricing approval and was not selected.

Before provisioning, obtain an approved regional estimate, e.g. a proposed USD 5/month STAGING alerts-only budget with actual thresholds at 50/80/100% and forecast alert at 100%. [Billing alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets) alone do not stop spending. Verify service eligibility before relying on any spend-cap budget. Add bounded metrics (operation/status only) for accepted/429/503, store latency/contention and active slots; alert on any store 503, occupied slots requiring reconciliation, daily budget exhaustion and abnormal denial volume. Avoid subject/key/payload labels or request-body logging. Do not configure these resources in this PR.

#87 must implement the real adapter and authoritative writer hook, prove two real processes/restarts against durable storage, validate IAM/ingress/no-bypass paths and cost controls, confirm idempotent receipts and reconciliation, pass review/CI, then obtain explicit activation authorization. The current offline tests do not prove any of those live properties. Do not enable promotion as part of rejection acceptance.

Rollback: disable both BFF command flags and corresponding Engine gates first; keep reads independent. Stop/drain writer executions, reconcile uncertain permits against audit evidence, preserve rate counters and review receipts, and revert the admitted integration only after no writes can execute. Never restore dispatch by dropping the store, clearing active slots blindly or enabling the old local-only limiter.
